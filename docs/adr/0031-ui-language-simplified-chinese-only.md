# ADR 0031：界面语言固定简体中文，移除多语言切换

日期：2026-09-07

## 状态

已接受

## 背景

ADR-0001 规划了中英文界面切换并已实现：`frontend/src/i18n.tsx` 维护 zh/en 两套词典，语言是全应用共享状态，顶栏按钮切换、`tod-lang` 经 localStorage 持久化，组件测试里有英文渲染断言。

维护中暴露的代价：

- 每条新增界面文案都要中英各写一份，测试还要断言键集合对齐；词条增长只快不慢。
- 项目的目标用户是中文航天工程人员，英文界面没有实际使用方。
- 双语状态机（Provider/裸渲染两条路径、语言持久化、`<html lang>` 同步）是一套只为切换而存在的复杂度。

用户决策：仅保留中文，去掉所有英文功能，不需要多语言界面。

## 决策

1. 界面语言固定简体中文，不提供切换。删除英文词典、`lang`/`setLang` 状态、`tod-lang` 持久化与顶栏切换按钮。
2. 词典收敛为单层 `Record<string, string>`（中文）。`t` 对缺失 key 返回 key 本身，暴露开发期漏配；不回退任何语言。
3. `<html lang>` 恒为 `zh-CN`。`I18nProvider` 挂载结构保留（main.tsx 与组件测试依赖），内部不再有语言状态。
4. 专业名词、工具名、字段名、协议名、科学缩写（CR3BP/GCRS/Δv 等）按领域惯例保留原文，不算翻译对象。
5. 助手输出遵循同一决策：每轮 prompt 注入固定的中文领域指令（要求始终简体中文回答），协议字段与工具名保持原文。

## 后果

- 英文界面用户不再被支持；如有需要须重新引入双语机制（本 ADR 届时废止）。
- 词条维护成本减半，新增文案只写中文；英文渲染断言类测试全部删除。
- ADR-0001 定义的国际化学术语（源语言、翻译回退）不再有对应实现，CONTEXT.md 的 UI Language 一节已按本决策改写。
